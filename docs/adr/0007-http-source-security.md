# ADR-0007：HTTP 数据源安全边界

- 状态：已接受
- 日期：2026-07-15
- 适用阶段：M3.2 及以后

## 背景

旧 type 0、type 1、type 4 数据源会把配置中的地址、请求头、扩展参数和播放结果带入网络请求。
这些值均属于不可信输入。Nexora 既要兼容常见旧源，又不能通过关闭证书校验、泄露凭据或允许
无限资源消耗来换取兼容率。

## 决策

1. 数据源 API 和远程 `ext` 只接受无用户信息、无片段的 HTTPS 地址。TLS 证书和主机名必须
   使用平台信任链正常校验，禁止 trust-all 和忽略证书错误。
2. 每次数据源操作使用站点独立超时，并以同一总截止时间覆盖远程 `ext`、主请求和可选海报
   回填，防止多阶段请求把总耗时成倍放大。
3. 单次响应、远程 `ext`、筛选参数、条目数、JSON 深度、XML 外部实体和播放请求头均设上限。
4. 明确拒绝 `localhost`、IPv4 私网/回环/链路本地/组播、IPv6 回环/链路本地/ULA 等字面地址。
   普通 HTTPS 主机名仍允许，以维持旧源兼容；当前版本不宣称能够完整阻止恶意 DNS 重绑定。
5. `PlaybackRequest`、网络请求和网络响应的字符串表示不得包含完整 URL、Cookie、Authorization、
   Token 或其他请求头值，只允许输出脱敏地址、请求头名称和大小等诊断元数据。
6. type 0/1 的列表结果缺少海报时，可以批量请求详情回填；回填失败保留已取得的主结果，不将
   辅助请求失败升级为整个数据源失败。
7. type 0/1 的播放地址只在 URL 路径明确为常见媒体格式时标记为直链。包含嵌套 `url=http`、
   `v=http` 或 HTML 解析页特征的地址必须标记为需要解析，不能因查询参数中的 `.m3u8` 误判。

## 影响与后续

- 依赖明文 HTTP、自签名证书、私网 IP 字面地址或不安全请求头的旧源会被结构化拒绝。
- SMB、WebDAV、NFS 等局域网存储不经过本 ADR 的数据源 HTTP 网关，后续由独立存储安全策略处理。
- 若未来需要支持可信局域网 HTTP 数据源，应另立 ADR，定义用户授权、DNS 解析/地址固定、重定向
  复检及凭据隔离，不能直接放宽当前默认策略。
- 完整 DNS 重绑定防护需要在网络层增加受控 DNS 解析与每跳地址复检，列为后续安全增强项。
