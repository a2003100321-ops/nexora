# ADR-0009：全源搜索的会话与来源标识

- 状态：已接受
- 日期：2026-07-16
- 适用阶段：M3.3 及以后

## 背景

全源搜索会同时请求多个速度和可靠性不同的数据源。用户连续修改关键词时，旧请求可能晚于新请求
返回；不同数据源也可能返回同名影片。若仅用标题或拼接字符串作为标识，结果会被错误覆盖、合并
或在配置刷新后失去用户的启停状态。

## 决策

1. 每次搜索使用单调递增的 `SearchSessionId`。输入变化通过 `flatMapLatest` 立即取消旧会话，状态
   接收端仍复核 session ID，迟到结果不得覆盖当前查询。
2. 350ms debounce 位于可取消的会话流内部；手动重试跳过 debounce，用户取消同时终止搜索和详情。
3. 搜索只并发执行已启用、明确支持搜索的 type 0/1/4 数据源，最多同时运行 6 个请求。每个来源
   独立呈现 Loading、Success 或 Failure；单源超时、异常或错误不得清空其他来源结果。
   单份配置最多启用 500 个站点，单次搜索也最多参与 500 个站点并以固定工作池执行；单源暂存
   50 条、界面聚合 2,000 条结果，达到上限时显示截断提示，防止不可信配置造成无界协程或结果
   内存增长。
4. M3 不按标题强制合并。每条原始结果保留 `sourceKey`、`vodId`、title、year、type、region、poster、
   `sourceName`，结构化身份为 `SourceVodIdentity(sourceKey, vodId)`。
5. 远程配置以规范化 HTTPS origin 的 SHA-256 作为配置身份输入，因此同一 URL 内容刷新时保持
   config ID 和 source key；本地文件和粘贴文本仍按规范化内容生成身份。身份中不保存明文 URL。
6. 同一远程配置刷新时，仅继承匹配站点的用户启停状态；搜索能力、可用性和其他新配置值仍以
   本次解析结果为准。
7. 搜索测试页只加载通过 HTTPS 和本机/私网地址检查的海报，不附加数据源 Cookie 或认证头。应用
   组合根提供专用 ImageLoader：保留平台默认 TLS 校验、拒绝任何解析到非公网地址的 DNS 结果、禁止
   重定向与自动重试，并限制超时、响应体大小和并行解码数量。点击结果只请求详情并展示线路名称与
   集名，不调用播放接口，也不显示 playback ID。

## 影响与限制

- 同名影片会保留为多个原始结果，为后续跨源合并提供可追溯输入。
- 远程配置迁移到新 URL 或更换查询参数会获得新身份；若将来需要识别轮换签名 URL，必须引入显式
  的可信配置 UUID 或用户确认合并，不能猜测两个地址属于同一配置。
- 当前只搜索 HTTP type 0/1/4。插件源在 M3.4 仍是隔离 fixture 原型，不进入真实全源搜索。
- 海报地址允许 HTTPS 签名查询参数以兼容 CDN，但不得出现在 Nexora 日志；专用 DNS 与禁重定向
  策略同时保护初始主机名和实际连接地址，Feature 模块不绑定具体网络实现。
