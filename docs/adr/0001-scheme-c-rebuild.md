# ADR-0001：采用方案 C 重建 Nexora

- 状态：已接受
- 日期：2026-07-15

## 背景

PickTV 1.3.3 可作为数据源格式和行为研究基线，但旧工程把应用、数据源、播放器、
存储和平台界面紧密耦合。直接在旧工程上改名或逐文件翻新，会把旧包结构、动态执行路径、
历史数据模型和难以验证的依赖继续带入 Nexora。

Nexora 是个人使用的全新 Android 影视播放器，不是 PickTV 的换皮版本。

## 决策

采用方案 C：

1. 建立全新的 Kotlin 多模块 Android 工程和独立 Git 历史。
2. PickTV 压缩包、解压源码、业务实现和二进制始终留在 Nexora 仓库之外。
3. 后续兼容工作通过边界清晰、可测试的旧数据源兼容桥完成；当前 M0～M2 只建立契约、
   安全策略和测试语料，不实现旧数据源运行时。
4. 新功能只依赖 Nexora 自有的模型和端口；若未来确需引入上游派生代码，必须先完成来源、
   许可证、修改和替代方案台账，并使用独立提交。
5. 旧实现按已验证的行为逐步替换，不承诺任意未知插件绝对兼容。

## 后果

- 手机和 TV 是两个独立应用模块，旧 PickTV `app` 与 flavor 结构不会进入新工程。
- 初始开发成本高于换皮，但依赖方向、安全边界和测试结果可以被持续验证。
- GPL-3.0、必要署名、NOTICE 和第三方台账继续保留。
- M3 数据源兼容实现必须得到新的阶段授权；本 ADR 不授权提前开发 M3。
