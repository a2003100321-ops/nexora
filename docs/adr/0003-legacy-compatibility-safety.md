# ADR-0003：旧配置兼容性的安全边界

- 状态：已接受
- 日期：2026-07-15
- 适用阶段：M0～M2；M3+ 延续本决策中的安全约束

## 背景

Nexora 需要尽可能兼容 PickTV 1.3.3 使用的数据源配置格式，包括站点、解析器以及
JAR、JavaScript、Python 插件的描述信息。但旧配置及其引用的远程内容都属于不可信输入，
而且任意第三方插件的行为、依赖、网络响应和原生代码无法由 Nexora 完整控制。

因此，“兼容”必须是可定义、可测试、可诊断的工程目标，不能解释为无条件执行未知代码，
也不能承诺未知插件达到 100% 行为一致。

## 决策

1. Nexora 的目标是对已知配置语法、字段语义和插件描述符实现可测试的高兼容，而不是对
   任意未知 JAR、JavaScript 或 Python 插件承诺 100% 兼容。
2. 配置解析与功能激活必须分离。`live`、`notice`、`drm` 等兼容字段应能够被识别和保留，
   但按产品策略标记为禁用：不得启动直播、展示公告或建立 DRM 播放会话。
3. M0～M2 只建设合成测试语料、清单门禁和兼容测试框架，不执行未知 JAR、JavaScript、
   Python、AAR、SO、DEX 或其他动态载荷。
4. 不得为兼容旧源而关闭 TLS 校验，不得接受信任所有证书或主机名的网络实现。
5. Android 主进程不得装载或执行任意动态代码。配置文本中的插件地址只作为描述数据处理，
   不能因为读取、验证或列举语料而触发下载、类加载、脚本求值、Python 启动或原生库加载。
6. 未知字段优先保留并产生可诊断结果；格式错误、安全超限和策略禁用必须使用不同错误类别，
   不能全部静默降级为空结果。

## M0～M2 已实现的门禁

- `test-corpus/legacy-config` 只包含原创合成、无秘密的 UTF-8 文本语料。
- `manifest.json` 明确声明 `syntheticOnly=true` 和 `pluginExecution=FORBIDDEN`，并为每个样本记录
  SHA-256、预期用途和预期结果。
- `:source:testkit` 校验清单、哈希、文件大小、路径穿越、符号链接、UTF-8 和未登记文件。
- 语料门禁在读取内容前拒绝 JAR、JavaScript、Python、AAR、SO、DEX、CLASS、APK、ZIP
  以及常见本机可执行文件扩展名。
- 当前合成样本覆盖最小配置、`live`、`notice`、DRM 播放结果、插件描述符和截断 JSON；
  插件地址使用 `example.invalid`，只用于描述符清点。

这些门禁只证明语料框架的边界，不代表旧配置 Decoder、Schema Parser、远程引用解析器、
插件运行时或完整兼容层已经实现。

## M3+ 计划与前置条件

M3+ 可以在本 ADR 约束下逐步实现纯数据 Decoder、Schema Parser、规范化中间模型和受控远程
引用解析。任何动态插件执行都必须另立 ADR 并完成威胁建模，至少满足：

- 独立隔离进程，不在 Android 主进程执行；
- 通过受限 IPC 暴露冻结的兼容协议；
- 网络、文件、Cookie 和持久化访问由受控接口代理；
- TLS 始终校验，且设置请求大小、重定向、并发和时间上限；
- 插件哈希或签名验证、明确的用户授权、单源超时和熔断；
- 插件崩溃、超时或不兼容只影响该数据源，并返回结构化诊断。

在这些前置条件未完成前，Nexora 可以识别插件描述符，但不得执行插件。

## 影响

- 高兼容将由版本化语料和回归结果衡量，结论可以复现。
- 某些依赖不安全 TLS、主进程权限或未知原生库的旧插件将被明确判定为不支持。
- 保留禁用字段可避免一项不支持功能导致整份配置导入失败，同时不扩大产品功能范围。
- 安全拒绝属于预期兼容结果，不应为了提高表面通过率而绕过门禁。
