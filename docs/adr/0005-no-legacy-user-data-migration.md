# ADR-0005：不迁移旧应用用户数据

- 状态：已接受
- 日期：2026-07-15
- 适用范围：PickTV 及其他旧应用数据到 Nexora 的迁移

## 背景

Nexora 是独立产品，不是 PickTV 数据库和用户状态的原位升级。旧应用数据可能包含收藏、
播放记录、偏好设置、设备信息、登录凭据、Cookie、Token、私有数据源地址以及无法可靠解释的
Room 表结构。自动发现或复制这些数据会引入隐私、授权、模式兼容和数据完整性风险。

数据源“配置格式兼容”与“迁移旧应用用户数据”是两件不同的事：前者描述如何理解用户明确
提供的配置文本，后者会扫描、读取或转换旧应用的持久化状态。

## 决策

Nexora 不迁移以下 PickTV 或其他旧应用数据：

- 收藏、追剧和媒体库状态；
- 播放历史、进度、搜索历史和最近使用记录；
- 应用设置、主题、播放器偏好和功能开关；
- 旧 Room 数据库、WAL、SHM、SharedPreferences 及其内部表；
- 登录状态、Cookie、Token、密码、设备标识和同步状态；
- 缓存、下载任务、日志及旧应用私有目录中的其他文件。

Nexora 不扫描旧应用的数据目录，不根据包名寻找旧数据库，也不提供从旧 Room schema 直接升级
到 Nexora schema 的迁移路径。Nexora 数据库从全新状态创建；将来的 Room migration 只服务于
Nexora 自身版本之间的升级。

本决策不否定未来的数据源配置兼容：在兼容解析器经过安全评审后，用户可以显式选择或输入一份
配置文本。该流程不得自动读取旧应用数据库或偏好，不得把凭据和用户状态视为配置格式的一部分，
也不得绕过 ADR-0003 的插件执行和网络安全边界。

## M0～M2 已实现的门禁

- PickTV 压缩包和解压目录保留在 Nexora 仓库之外，只用于只读审计。
- 仓库忽略旧源码归档、真实配置、密钥、Token、Cookie、日志和来源不明的二进制载荷。
- `test-corpus/legacy-config` 的清单要求全部样本为原创合成文本；当前没有真实用户配置或旧数据库。
- `:source:testkit` 只验证语料清单和文件安全属性，不读取 PickTV 配置、数据库或应用私有目录。

这些措施表示“不导入旧用户数据”的门禁已经建立，不表示配置导入、数据库转换或用户数据导出
功能已经实现。

## M3+ 计划与例外处理

M3+ 默认继续采用全新 Nexora 数据库和空用户状态。若未来确有跨设备导入或导出需求，必须：

1. 另立 ADR，明确数据分类、用户授权、加密、版本和失败回滚；
2. 使用 Nexora 定义的中立、版本化交换格式，而不是读取旧 Room 文件；
3. 由用户主动选择文件并确认字段范围，不进行后台扫描或静默导入；
4. 默认排除凭据、Cookie、Token、设备标识和插件二进制；
5. 使用合成或正式脱敏的数据进行测试。

这类未来功能不追溯性改变本 ADR：PickTV 收藏、记录、设置和旧 Room 仍不属于 Nexora 的迁移输入。

## 影响

- 用户首次使用 Nexora 时需要重新添加数据源，并重新建立收藏、历史和偏好。
- 项目无需维护不可靠的 PickTV Room schema 映射或处理旧凭据。
- 隐私和数据损坏风险显著降低，Nexora 的数据库生命周期保持独立、可测试。
- 配置兼容率不会被收藏、播放记录或旧设置的迁移结果混入。
