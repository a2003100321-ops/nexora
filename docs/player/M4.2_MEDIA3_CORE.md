# M4.2a Media3 Core Engine

状态：已实现最小 Media3 播放闭环，本地验证通过，等待远端 CI。

范围：仅接入 `player:media3` 的 Media3 / ExoPlayer 最小核心能力。本阶段不包含播放器 UI、字幕、弹幕、投屏、DRM、VLC、后台服务或自动换源。

## 已实现内容

- `Media3Engine` 实现 `PlayerEngine`。
- `Media3MediaItemMapper` 负责从 `PlaybackSessionRequest` 创建 Media3 `MediaItem`。
- `ExoPlayerMedia3PlayerAdapter` 封装真实 `ExoPlayer`。
- `SecureMedia3DataSourceFactory` 基于 Nexora `NetworkPolicy` 创建 Media3 HTTP DataSource。
- Media3 播放事件转换为 Nexora `PlayerEngineEvent`，由 runtime 继续转换为 `PlaybackState` 与 `PlayerEvent`。
- Media3 错误码转换为 Nexora `PlayerErrorCode`。

## 支持格式

- MP4：按 `.mp4` / `.m4v` 推断为 `MimeTypes.VIDEO_MP4`。
- HLS：按 `.m3u8` 推断为 `MimeTypes.APPLICATION_M3U8`。
- DASH：按 `.mpd` 推断为 `MimeTypes.APPLICATION_MPD`。

## 已实现命令

- `prepare`
- `play`
- `pause`
- `seek`
- `stop`
- `close`，对应释放 Media3 / ExoPlayer 资源

## 安全网络策略

DataSource 不直接接受任意 URL。`PlaybackSessionRequest` 必须先经过：

- URL 校验：M4.2a 只接受 HTTPS URL，拒绝明文 HTTP、缺失 host、userinfo。
- Header 白名单：仅允许播放所需的安全请求头，例如 `User-Agent`、`Accept`、`Range`、`Referer`、`Origin`。
- Cookie Provider：Cookie 只能由 `PlaybackCookieProvider` 注入，不能从普通 headers 透传。
- Credential Provider：授权信息只能由 `PlaybackCredentialProvider` 注入，当前允许 `Authorization` 和 `X-Api-Key`。

本阶段没有实现自动重试。错误恢复策略留到后续阶段。
