# M4.3a 基础播放器 UI

## 阶段目标

M4.3a 只建立 Nexora 手机版的最小可用播放器界面，并验证 UI 到播放器核心链路：

```text
Player UI
  ↓
PlayerController
  ↓
Runtime
  ↓
Media3Engine
```

本阶段不开发字幕、弹幕、倍速、清晰度切换、音轨、选集、手势、投屏、DRM、VLC 或自动换源。

## 已实现内容

### 播放页面

`feature:player` 新增 `PlayerRoute` 与 `PlayerScreen`，提供：

- 视频渲染区域占位；
- 返回按钮；
- 播放/暂停按钮；
- 播放进度条；
- 当前播放时间；
- 总时长；
- 全屏按钮占位。

全屏按钮在 M4.3a 只作为 UI 控件存在，不执行横竖屏或沉浸式切换。

### 状态映射

新增 `PlayerScreenState`，把播放器核心状态转换为 UI 可直接消费的字段：

- 标题；
- 中文状态文本；
- 当前进度；
- 总时长；
- 进度比例；
- 播放/暂停按钮文案；
- seek 是否可用。

`PlaybackState.Buffering`、`PlaybackState.Playing`、`PlaybackState.Paused` 增加 `durationMs`，用于让 UI 在播放中显示总时长与进度比例。

### 手机版入口

`app-mobile` 首页增加“打开基础播放器”按钮，用于进入 M4.3a 测试播放页。

当前入口使用一个 HTTPS MP4 示例 `PlaybackSessionRequest`，仅用于验证播放闭环。该入口不会替代后续正式详情页或播放入口。

### 控制器持有方式

`app-mobile` 新增 `MobilePlayerViewModel`：

- 创建 `RuntimePlayerController`；
- 注入 `Media3Engine`；
- 通过 `viewModelScope` 持有控制器生命周期；
- 页面销毁时派发 `PlayerCommand.Close`。

UI 不直接持有或调用 ExoPlayer，也不依赖 Media3 类型。

## 生命周期策略

M4.3a 新增 `PlayerLifecycleCoordinator` 的纯 Kotlin 生命周期协调模型，用于表达基础策略：

- 进入播放器：记录进入状态；
- 返回：发出 `PlayerCommand.Stop`；
- 横竖屏切换：不停止播放，由 ViewModel 保持 Controller；
- APP 进入后台：不由 Activity 直接停止播放器；
- APP 恢复前台：恢复 UI 对当前状态流的观察。

Activity 不管理播放器状态。

## 测试覆盖

新增测试覆盖：

- `PlayerScreenStateTest`：验证播放器状态到 UI 状态的映射；
- `PlayerLifecycleCoordinatorTest`：验证进入、返回、横竖屏、后台、恢复的基础生命周期策略；
- `PlayerControllerCallTest`：验证 UI 入口层需要的 open、play、pause、seek、stop 命令会经由 `PlayerController`。

同时保留 M4.1/M4.2 的 runtime 与 Media3 相关测试。

## 当前限制

- 视频渲染区域在 M4.3a 是基础容器/占位，真实播放器 Surface 绑定与沉浸式横屏体验留到后续播放器 UI 阶段。
- 全屏按钮暂不执行功能。
- 不支持字幕、弹幕、倍速、清晰度切换、音轨、选集、手势。
- 不处理自动重试、自动换源、投屏、DRM。
- 测试入口使用内置 HTTPS 示例播放请求，不代表正式内容详情页。

## 验收命令

建议执行：

```powershell
.\gradlew.bat :feature:player:testDebugUnitTest --no-daemon
.\gradlew.bat quality --no-daemon
.\gradlew.bat :app-mobile:assembleDebug :app-tv:assembleDebug --no-daemon
```

## 后续阶段边界

M4.3a 完成后停止。高级播放器 UI、真实 Surface 绑定、字幕、弹幕、清晰度、音轨、选集和手势控制均不在本阶段实现。
