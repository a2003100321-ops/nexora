# M4.1 Player Runtime Core Implementation

状态：已实现核心闭环，本地验证通过，等待远端 CI。

范围：播放器契约、runtime 状态机、FakePlayerEngine 与单元测试。本阶段不包含正式播放内核、播放器 UI、弹幕、投屏、DRM、VLC 或自动换源。

## 已实现模块

### player:api

- `PlaybackSessionRequest`
- `PlayerController`
- `PlayerEngine`
- `PlaybackState`
- `PlayerCommand`
- `PlayerEvent`
- `PlayerErrorCode`
- `Capability`

`player:api` 只依赖 Kotlin、Coroutines Flow 和 Nexora 基础模型模块。它不引用 Media3、ExoPlayer、Android UI、Source DTO 或 Room。

### player:runtime

- `RuntimePlayerController`
- 单写者 reducer
- `PlaybackGeneration` 管理
- `PlaybackCommandId`
- `PlaybackOperationId`
- 状态流转
- close 后拒绝新命令
- 过期 engine 回调丢弃
- `FakePlayerEngine`

`RuntimePlayerController` 暴露 `StateFlow<PlaybackState>` 与 `Flow<PlayerEvent>`。Activity 或 UI 层未来只订阅状态和发送命令，不直接持有播放器状态机。

## 已覆盖测试

- `Idle -> Preparing`
- `Preparing -> Playing`
- `Playing -> Paused`
- `Buffering -> Playing`
- `Error` 后重新打开创建新 generation
- 新播放覆盖旧回调
- 换线路 generation 丢弃旧结果
- close 后拒绝命令
- completed 事件进入完成状态

测试使用 `FakePlayerEngine`，不依赖真实视频、网络或 Media3。

## 当前限制

- `PlaybackSessionRequest.resource` 仍是播放器契约层输入，真正的资源保险箱和短租约将在后续播放器编排层中实现。
- `FakePlayerEngine` 只用于状态机和命令测试，不代表真实播放器能力。
- `RuntimePlayerController` 已具备 generation 丢弃策略，但真实线路切换的预加载和无缝切换留到 Media3 接入后评估。
- 错误恢复目前通过重新 `Open` 同一请求验证；更细粒度 retry 策略将在 M4.2 以后补充。
